# Related products, research and practices to adapt

Reviewed 28 October 2026. This compares public primary sources, not privately tested competitors. Vendor capabilities below are their published descriptions; their accuracy and business outcomes were not independently verified. No external source code or proprietary workflow has been copied.

## Positioning decision

Guided assembly, visual inspection and repair loops already exist. ProofLoop should not claim to have invented them or to outperform deployed manufacturing systems. Its testable direction is a **small, inspectable verification layer for Meta-powered physical agents**: exact task contracts, evidence insufficiency, bounded follow-up, replayable decisions and explicit separation between a state observation and an executed action.

The current project is a prototype evaluated on selected recordings and controlled software fixtures. It has no validated customer demand or demonstrated general accuracy advantage over Spark alone. Features should strengthen the evidence behind this narrower contribution.

| [REFLECT](https://robot-reflect.github.io/) | Summaries of observations support failure explanation and correction. | Add deterministic expected → observed → decision → permitted next action explanations. Keep the physical cause unobserved unless separately supported. | A wrong region does not establish why an operator or robot put an object there. This is a limited adaptation, not a reproduction of REFLECT's robot experiments. |
| [SayCan](https://say-can.github.io/) | Language-based usefulness is separated from grounded skill feasibility. | Keep semantic suggestions separate from executable predicate checks. | [KnowNo](https://robot-help.github.io/) | Asking for help is treated as part of robot uncertainty handling. | Preserve UNKNOWN and targeted requests; compare accepted/abstained decisions and explicit denominators. | Our thresholds and two-attempt budget do not inherit conformal calibration or statistical guarantees. |
| [Rerun timelines](https://rerun.io/docs/concepts/logging-and-ingestion/timelines) | Sensor data and derived results share explicit timelines for inspection. | Link disagreement selection to the exact source pair and show source grouping; separate source time, current freshness and recorded historical reasoning. | We adapt the inspection principle. ## Implementation order and acceptance

1. **Explain the actual discrepancy.** Bind explanations to exact check IDs, expected regions and supported observations. UNKNOWN must not turn into an invented physical cause or a move instruction. Historical explanations must remain historical.
2. **Expose failure modes.** Recompute paired comparisons from validated reports. Keep known FAIL acceptance separate from acceptance of ground-truth UNKNOWN; show coverage beside accuracy among decided cases. A cohort without FAIL controls must display that missing denominator. Selecting a disagreement must select its original images.
3. **Challenge semantic anchors.** Freeze a small packet/label-versus-candy test and positive glass/candy controls before inference. A separate source-bound challenger may add support or remain UNKNOWN, but cannot independently certify identity or alter existing placement results. Report positive-case abstention and extra inference cost.
4. **Stress changed task contracts.** Keep images, regions, concepts and the perception method fixed while changing the required region under a newly reviewed contract. Recompute predicates from saved SAM results and call Spark again for the changed requirement. Report reuse and incremental cost explicitly; never reuse a verdict bound to the old specification.

These changes need semantic tests, browser interaction checks and public-safe experiment records before publication. Complete physical procedures, causal action verification and another person's practical use remain separate validation work.
