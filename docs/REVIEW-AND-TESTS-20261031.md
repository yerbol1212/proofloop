# Engineering review and evidence limits — 31 October 2026

ProofLoop has stronger evidence handling, but useful perception remains the main weakness. The latest candidate passes its software checks and fails its declared capability gate. More infrastructure, a large test count and a clean external code review do not turn that failure into demonstrated operator benefit. This assessment concerns the repository and its recorded experiments; it is not a Meta endorsement or a prediction of hackathon results.

## Production defects corrected

| Priority | Reproduced defect | Correction and regression evidence |
| --- | --- | --- |
| P2 | An uploaded pair acquired a new freshness window when its queued job finally dispatched. Admission at time `100000`, followed by a `31001` ms queue wait, could still spend four fixture calls and return PASS with current age zero. | Private server admission anchors now bind the original wall and monotonic clocks to the request, decoded source hashes, exact job binding and local runtime scope. Queue dwell and inference consume the same nondecreasing age. Expired queued evidence is rejected before model calls; a twenty-second queue plus fifteen seconds of fixture inference produces UNKNOWN, while the twenty-five-second positive control remains supported. |
| P2 | A successful inspection could inherit an unrelated recovery receipt after switching tasks, or reference an earlier recovery from another revision of the same task. | Task activation clears current references while preserving historical files. Job publication freshly replays saved recovery evidence and requires matching task hash, protocol hash, completed revision, receipt hash and outcome. An unrelated or missing receipt is omitted without rewriting a separately supported visual result. A genuinely matching completed repair retains its reference. |

The [admission and receipt investigation](ADMISSION-AND-RECEIPTS-20261031.md), [queued-capture tests](../tests/test_queued_capture.py), [inspection service](../proofloop/job_service.py) and [interactive engine](../proofloop/interactive.py) describe these fixes. These are ordinary workflow correctness defects, reproduced with authored images, fake model clients and injected clocks. They are separate from perception accuracy.

Additional controls prevent a changed key, calibration, view order or supported library entry point from refreshing the age of known admitted source bytes. Pending pairs sharing either exact decoded source inherit the relevant earlier clock. Polling preserves observed elapsed high-water marks, so a later wall-clock rollback cannot revive evidence. The live admission registry is bounded to thirty-two entries and pruned at terminal cleanup. A new runtime without an original anchor rejects pending work before inference rather than inventing a new clock from a historical creation timestamp.

Cancellation conservatively retires the admitted views: a new inspection needs different fresh images even if the cancelled pair was still within its window. Historical job events and saved receipts remain unchanged. Exact-byte reuse checks do not authenticate edited images, recompressed copies or capture time; upload freshness still depends on an operator declaration. A thirty-second freshness ceiling is an upper bound, and individual checks can expire earlier. A receipt may remain valid history at its decision point after current evidence and workflow authority have expired.

None of these regression checks performs paid inference or qualifies perception accuracy; zero review findings do not establish an absence of defects.

A separate [conditional containment-witness diagnostic](CONTAINMENT-WITNESS-PLAN-20261031.md) has passed independent prepublication review. It concerns an explicitly declared whole-projection containment hypothesis, rather than assuming that every generic location check has that meaning. Under fallible target-membership assumptions, model-supported material outside a goal could support a conditional geometric counterexample. It must preserve the original core verdict, create no task-violation assertion or whole-object location, provide no repair origin and grant no PASS or current authority. Original semantic/contact vetoes, confidence, stability, oldest-source age and boundary-crossing policies remain binding.

The diagnostic's fifteen authored fixture tests pass on both Python versions. The expanded full suite passes **1,585 tests on Python 3.12 in 108.245 seconds and Python 3.9 in 100.409 seconds**, with five expected optional-dependency skips on 3.9. ## Ranked next work

1. **P1 — Demonstrate useful decisions before adding more infrastructure.** Define a narrow task where both supported positives and a correct negative decision matter. Preserve the full denominator, refuse unsupported acceptance and report positive retention alongside UNKNOWN coverage. Do not lower thresholds or reinterpret exposed references to recover this failed candidate. The current one-decision result is insufficient for broad manufacturing or physical-workflow claims.
2. **P1 — Improve automatic tool coverage under a new explicit candidate.** Preserve the failed method and first identify whether automatic localization, SAM extent or the coverage assessment causes false refusal. Use separately declared component controls before another task trial. The completed zero-call diagnostic can explain partial material under a separate hypothesis; it must not become an acceptance shortcut or repair origin.
3. **P1 — Establish operator benefit when the deferred trial resumes.** Follow the prepared trial on a bounded, appropriate task and record successful verification, refusal, correction attempts and time against an ordinary manual check. A video-state agreement or a valid receipt does not independently prove that a requested physical action was executed. Keep the trial deferred until the participant resumes it.
4. **P2 — Protect a genuine new-source comparison.** Leave the prepared recordings unevaluated until a separately declared candidate meets its development gate. Freeze source selection, labels, thresholds, stopping rules and comparison methods before new inference. Resolve media redistribution rights before publishing source assets. Small exposed development results cannot supply a general accuracy claim.
5. **P2 — Measure the actual end-to-end path before optimizing it.** Separate queue age, provider time, integrity replay, persistence and response delivery. Repeated validation dominates the experimental harness, but any caching or reuse must preserve exact source/code bindings and the nondecreasing freshness floor. A faster implementation is useful only if a separately tested change preserves those invariants.

The immediate engineering priority is useful, honestly bounded perception and observable operator value. The repaired admission and receipt invariants make those future tests more credible; they do not supply the missing capability evidence themselves.
